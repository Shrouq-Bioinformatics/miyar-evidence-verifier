# مِعيار | MIYAR — التوثيق النهائي

**تاريخ التحقق من حالة المشروع:** 2026-10-06
**النطاق:** التوثيق يصف التنفيذ الحالي، ولا يضيف أو يغيّر وظائف المنتج.

## 1. نبذة المشروع

**اسم المشروع:** مِعيار | MIYAR

**الوصف:** «مِعيار منصة ذكية للتحقق من جودة المحتوى الإسلامي قبل النشر. يحلل
النص إلى ادعاءات قابلة للتحقق، ويربط كل ادعاء بالمصدر المناسب، ثم يعرض حالة
الدليل والمصدر والموضع وسبب النتيجة بصورة واضحة وقابلة للتتبع.»

**الموضع الأساسي:** مِعيار لا يكتب المحتوى بدل المستخدم؛ بل يتحقق مما سيُنشر.

## 2. المشكلة

- وجود مرجع لا يعني بالضرورة أن المرجع يثبت الادعاء نفسه.
- قد تكون الإحالة غير دقيقة، أو يكون الدليل متعلقًا بالموضوع لكنه غير كافٍ.
- قد يكون نطاق المصدر أضيق من التعميم الوارد في المحتوى.
- قد يكون التحقق اليدوي بطيئًا ومشتتًا بين النص والمراجع.
- يحتاج المستخدم إلى نتيجة تربط الادعاء بالدليل ومصدره وموضعه وسبب التقييم.

لا تعني هذه المشكلات أن كل محتوى يحتاج إلى الحكم الآلي؛ دور مِعيار هو تنظيم
خطوة التحقق وإظهار حدود ما أمكن استرجاعه.

## 3. الحل ومسار التحقق

1. يلصق المستخدم محتوى إسلاميًا موجودًا.
2. يساعد نموذج الذكاء الاصطناعي على فهم النص واستخراج الادعاءات القابلة للتحقق.
3. يصنف النظام مجال الادعاء.
4. يوجّه البحث إلى مزود متاح ومناسب للمجال.
5. يسترجع نص الدليل وموضعه، عند توافر نتيجة مطابقة.
6. يقيّم النظام العلاقة بين الادعاء والدليل، ويتحقق من الإحالة الصريحة عند
   وجودها.
7. تعرض الواجهة الادعاء والحالة والمصدر والموضع والاقتباس وسبب النتيجة.

**المسار القابل للتتبع:** الادعاء ← الدليل ← المصدر ← الموضع ← الحالة.

إذا لم يتوفر دليل كافٍ أو كانت المطابقة غير مؤكدة، لا تختلق مِعيار دليلًا
مؤيدًا. وتبقى النتيجة محدودة بالنص والمصدر والنطاق اللذين جرى التحقق منهما.

## 4. الحالات الظاهرة للمستخدم

| الحالة | معناها للمستخدم |
|---|---|
| **موثق** | عُثر على دليل مباشر مناسب ضمن المصدر والنطاق اللذين جرى فحصهما. لا يعني ذلك حكمًا عامًا خارج ذلك النطاق. |
| **الدليل غير كافٍ** | لم يظهر دليل مسترجع كافٍ لدعم الادعاء؛ لا تعني هذه الحالة وحدها أن الادعاء باطل. |
| **تعارض في الإحالة** | الإحالة الصريحة لا تطابق السجل المسترجع، مثل رقم حديث غير مطابق؛ لا يُصحح الرقم بصمت لتقديم نتيجة مؤيدة. |
| **يحتاج مراجعة بشرية** | يقتضي الالتباس أو تعقيد الادعاء مراجعة مختص؛ لا يُنشأ مثال أو دليل لهذه الحالة ما لم تُرجعها الخدمة فعلًا. |

لا تعرض الوثائق التقنية أسماء الحالات الداخلية بوصفها حالات للمستخدم.

## 5. دور الذكاء الاصطناعي

يستخدم الخادم OpenAI لتحليل النص، واستخراج الادعاءات، وتصنيف المجال، والمساعدة
في توجيه البحث، ومقارنة الادعاء بالدليل المسترجع، وصياغة تفسير عربي للنتيجة.
الإعداد الافتراضي للنموذج هو `gpt-4.1-mini` ويمكن تغييره عبر `OPENAI_MODEL`.

**الذكاء الاصطناعي ليس مصدر الدليل.** يجب أن يأتي الدليل من مزود مصدر متصل
ويُعرض مع مصدره وموضعه. وجود عبارة قريبة في النص لا يساوي دعمًا مباشرًا، وظهور
المصدر لا يثبت صحة تعميم شامل.

عند فشل استرجاع المصدر أو غياب المطابقة، تُعرض فجوة الدليل بدل اختلاق نص أو نسبة
النتيجة إلى مصدر لم يُسترجع.

## 7. قواعد سلامة النطاق والإسناد

- **الحديث:** لا يُستبدل رقم صريح خاطئ برقم محتمل صحيح لتبرير الادعاء.
- **السيرة:** نسبة نص إلى ابن هشام لا تثبت صحة حديث أو مرتبته.
- **التفسير:** تفسير آية ذات صلة لا يثبت تلقائيًا ادعاءً أوسع من نطاق النص.
- **عمومًا:** الدليل المرتبط بالموضوع لا يساوي دليلًا مباشرًا على الادعاء.
- **عمومًا:** ورود العبارة في مصدر لا يحوّلها إلى حقيقة عامة أو إجماع شامل.
- عند غياب المصدر أو فشل الاتصال، لا يُعرض ملخص مولّد على أنه اقتباس أصلي.

التدفقات المسجلة في Replit توجّه الواجهة على `/` وخدمة API على `/api`، وتوفر
متغيرات `PORT` و`BASE_PATH`.

## 9. الخصوصية

- سجل التحقق محفوظ محليًا في متصفح المستخدم، ولا يتطلب حسابًا.
- لا يُنشئ الخادم تاريخ تحقق للمستخدم أو قاعدة بيانات لسجلاته.
- يُرسل النص إلى OpenAI من خلال الخادم لأغراض التحليل وإنتاج النتيجة.
- لا ينبغي إدخال بيانات شخصية أو سرية في نص التحقق.
- حذف السجل المحلي أو مسحه يزيل النسخ المحفوظة في متصفح ذلك الجهاز؛ لا يصف ذلك
  سياسات الاحتفاظ الخاصة بمزود خارجي.

## 10. الإعداد والتشغيل

المتطلبات: Node.js و`pnpm`، واستخدام نسخة المشروع المعتمدة في ملف القفل
`pnpm-lock.yaml`.

```sh
pnpm install
```

في Replit، تُستخدم تدفقات العمل المسجلة لخدمة API والواجهة، وهي تضبط مسارات
الخدمات ومتغيرات `PORT` و`BASE_PATH`.

للتشغيل المحلي المنفصل من جذر المستودع، في طرفيتين:

```sh
PORT=8080 pnpm --filter @workspace/api-server run dev
```

```sh
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/miyar run dev
```

فحص API المحلي:

```sh
curl http://localhost:8080/api/healthz
```

يحتاج تشغيل التحقق المدعوم بالذكاء الاصطناعي إلى `OPENAI_API_KEY`. انسخ
`.env.example` لتوثيق أسماء المتغيرات، ثم أدخل القيم في Replit Secrets أو البيئة
المحلية الآمنة. لا تضع أسرارًا في المستودع ولا تعتمد على ملف `.env` في بيئة
النشر. عند التشغيل المحلي المباشر، يجب أن يوجّه reverse proxy مسار `/api/*` إلى
خدمة API؛ توجيه Replit المسجل يوفر ذلك في بيئة المشروع.

## 11. الاختبارات والتحقق

الأوامر الموجودة في `package.json`:

```sh
pnpm --filter @workspace/api-server run typecheck
pnpm --filter @workspace/miyar run typecheck
pnpm --filter @workspace/api-server run test:providers
pnpm --filter @workspace/api-server run build
PORT=18726 BASE_PATH=/ pnpm --filter @workspace/miyar run build
```

لا يوجد أمر `test` عام في الجذر؛ مجموعة اختبارات المزودين هي أمر الاختبار
المسجل أعلاه. يحتوي التشغيل الذي جرى في 2026-10-06 على 18 اختبارًا ناجحًا من
18، وفحوص أنواع ناجحة للواجهة والخادم. فحص الصحة أعاد HTTP 200 مع
`{"status":"ok"}`.

### حالات تحقق موثقة

| الحالة | نص الاختبار/الغرض | النتيجة الفعلية |
|---|---|---|
| آية قرآنية | «ورد في القرآن الكريم أن الله يأمر بالعدل والإحسان في سورة النحل، الآية 90.» | «موثق» مع دليل Tanzil وموضع سورة النحل، الآية 90. |
| رقم حديث خاطئ | «حديث «إنما الأعمال بالنيات» رواه البخاري برقم 999999.» | «تعارض في الإحالة»؛ لا يُصحح الرقم بصمت. |
| نطاق غير متصل | ادعاء الإجماع اعتمادًا على مختصر القدوري | «الدليل غير كافٍ»؛ مختصر القدوري قيد الربط. |
| سلامة السيرة | منع مساواة نسبة نص إلى ابن هشام بتوثيق حديث | مغطى باختبار مزود السيرة. |

لا تُعرض «يحتاج مراجعة بشرية» كأنها نتيجة اختبار ما لم تُرجعها الخدمة فعلًا.
من المعروف في حالات العرض الاختباري أعلاه أن عدد نتائج المراجعة البشرية صفر.

## 12. الأثر المتوقع والتقييم

القيمة المقصودة هي تقليل الخطوات اللازمة للعثور على إحالة مرتبطة، وجمع الادعاء
والدليل والمصدر والموضع في واجهة واحدة، وإظهار فجوات الأدلة أو عدم مطابقة
الإحالة قبل النشر. هذه فوائد مستهدفة، وليست قياسًا عامًا مثبتًا.

**اختبار استخدام أولي محدود على مستخدمين اثنين.** النتائج أولية ومحدودة ولا
تُعمم. لا تُضاف نتائج فردية أو أرقام غير موثقة.

لا يذكر هذا الملف مقارنة زمنية عامة. إذا أضيفت مقارنة «49 ثانية يدويًا مقابل
11 ثانية بمِعيار»، فيجب وسمها «اختبار أولي محدود لحالة واحدة» وعدم تعميمها.

## 13. الابتكار

يركز مِعيار على تقييم الادعاء على مستوى الادعاء نفسه، لا على توليد إجابة عامة
أو البحث عن نص قريب فحسب. وتشمل عناصره:

1. استخراج الادعاءات القابلة للتحقق من المحتوى.
2. تقييم علاقة الدليل بالادعاء بدل الاكتفاء بوجود مرجع.
3. مراعاة نطاق المصدر وطبعة النص والموضع.
4. كشف تعارض الإحالة الصريحة.
5. الإبلاغ عن فجوة الدليل عند عدم كفايته.
6. إظهار حالة للمراجعة البشرية عند الحاجة فقط إذا كانت نتيجة الخدمة الفعلية.
7. حفظ مسار النتيجة: الادعاء ← الدليل ← المصدر ← الموضع ← الحالة.

وهذا يختلف عن البحث التقليدي عن محتوى إسلامي ذي كلمات مشابهة؛ التشابه اللفظي
وحده لا يثبت الادعاء.

## 14. الحدود الحالية

- ليست كل عائلات المصادر المستهدفة متصلة؛ المصادر المذكورة «قيد الربط» ليست
  حية.
- يتوقف نوع الأدلة المتاحة على اتصال مزود المصدر وملاءمة المادة المسترجعة.
- قد تؤثر أعطال الشبكة أو إتاحة مزود خارجي في الاسترجاع.
- لا يُعد مِعيار بديلًا عن المختص أو المراجعة العلمية المتخصصة.
- قد تحتاج الادعاءات الملتبسة أو المركبة إلى مراجعة بشرية.
- اختبار استخدام أولي محدود على مستخدمين اثنين؛ النتائج أولية ومحدودة ولا
  تُعمم.

## 15. الأدوات المستخدمة

**أدوات بناء المشروع:** Replit، React، TypeScript، Vite، Node.js، Express،
OpenAI API، و`pnpm`. يستخدم GitHub كمستودع عام للكود والتوثيق النهائي.

**خدمات المصادر، منفصلة عن أدوات البناء:** Tanzil، QuranEnc،
HadithWeb/بوابة السنة التابعة للرئاسة العامة للبحوث العلمية والإفتاء.

## 16. الملفات والبنية

- `artifacts/miyar/` — واجهة الويب ومسارات `/`, `/verify`, `/sources`,
  `/history`.
- `artifacts/api-server/src/routes/` — مسارات خدمة API.
- `artifacts/api-server/src/lib/` — التحقق ومزودو الأدلة وسلامة المصدر.
- `artifacts/api-server/data/tanzil-quran/` — نص Tanzil وبياناته الوصفية.
- `artifacts/api-server/data/upstream-miyar/` — وثائق منشأ وترخيص تنفيذ
  QuranEnc المقتبس.
- `artifacts/api-server/tests/` — اختبارات مزودي المصادر وسلامة الإحالات.
- `artifacts/miyar-competition-demo/` — أثر الفيديو ومعاينته ومواد العرض.
- `docs/` — وثائق المسابقة وقائمة التحقق.

لا توجد مجموعة محلية للحديث أو التفسير أو السيرة ضمن `data/`؛ هذه النصوص
المذكورة تُسترجع من الخدمات الخارجية المتصلة.

## 18. أمن GitHub وسلامة البيانات

- `.env.example` يحتوي أسماء متغيرات وقيمًا فارغة فقط.
- `.gitignore` يستثني ملفات `.env` عدا المثال الفارغ، ومفاتيح البيئة الخاصة،
  والسجلات، والنسخ الاحتياطية وقواعد البيانات المحلية، وبيانات المستخدم المحلية،
  و`.agents/`.
- لا تضع مفاتيح API أو كلمات مرور أو رموز وصول أو قيم Replit Secrets في GitHub.
- لا ترفع سجلات تحقق المستخدمين؛ التطبيق لا يخزنها على الخادم، والسجل المحلي
  يبقى في متصفح المستخدم.
- لم يُعثر في الملفات المنشورة الحالية على قيمة مفتاح/اعتماد فعلي أو قاعدة
  بيانات لسجل مستخدم. تُعاد مراجعة الملفات قبل كل نشر عام.
- إضافة تجاهل إلى `.gitignore` لا تمحو محتوى سبق دفعه إلى تاريخ GitHub؛ إذا سبق
  نشر ملف حساس، يلزم إجراء منفصل لمعالجة تاريخ المستودع وتدوير السر المتأثر.
