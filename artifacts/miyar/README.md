# مِعيار | MIYAR

## الفكرة

مِعيار أداة عربية لمراجعة النقول والادعاءات الإسلامية قبل النشر. لا يكتب
المحتوى بدل المستخدم؛ بل يفصل النص إلى ادعاءات ويعرض الدليل والموضع وسبب
النتيجة وحدودها عند توفر مصدر متصل.

## المشكلة

قد يذكر المحتوى مرجعًا صحيح الاسم أو الرقم من دون أن يثبت المرجع الادعاء نفسه.
يعرض مِعيار النص المسترجع وموضعه، ويميّز بين الدليل المباشر والدليل غير الكافي
وتعارض الإحالة والحالات التي تحتاج إلى مراجعة بشرية.

## كيف يعمل مِعيار

1. ألصق المحتوى كما هو في `/verify`.
2. يستخرج مِعيار الادعاءات القابلة للتحقق ويربط كل ادعاء بالمجال المناسب.
3. يبحث في المصادر المحلية المتصلة ويقارن نص الدليل بالادعاء.
4. يعرض النتيجة والمصدر والموضع والاقتباس وسبب النتيجة في الصفحة نفسها.

المسارات العامة: `/`, `/verify`, `/sources`. نقطة التحقق الوحيدة هي
`POST /api/verify/public`، وفحص الخدمة على `GET /api/healthz`.

## المصادر

- القرآن الكريم: Tanzil Simple Clean 1.1 مع بيانات السور والآيات 1.0. يتحقق
  التطبيق من 114 سورة و6,236 آية عند تحميل المجموعة.
- مزود الحديث الرسمي ومصادر التفسير والعقيدة والفقه والسيرة والشبهات
  والمصطلحات ظاهرة في صفحة المصادر بوصفها «قيد الربط في النسخة الحالية»، ولا
  تُعرض كأدلة مستخدمة.
- لا تُستخدم سجلات الحديث التجريبية القديمة كدليل.
- لا يوصف ادعاء بأنه موثق إلا عند وجود نص مصدر مسترجع ومحدد يدعمه مباشرة.

تفاصيل مصدر Tanzil وترخيصه محفوظة في
`artifacts/api-server/data/tanzil-quran/README.md`.

## دور الذكاء الاصطناعي

يستخدم OpenAI لتحليل النص واستخراج الادعاءات وتقييم صلة الدليل المسترجع. مخرجات
النموذج ليست دليلًا: لا يمكنها وحدها توثيق ادعاء، ولا تُختلق أدلة عند غياب
المصدر.

## حدود الاستخدام

مِعيار أداة مساعدة للتحقق من الأدلة والإحالات، ولا يستبدل المختص عند الحاجة إلى
حكم شرعي شخصي أو مراجعة علمية متخصصة. يقتصر الإدخال على 12,000 حرف. «الدليل غير
كافٍ» لا يعني ثبوت الادعاء أو بطلانه.

## البنية التقنية

- الواجهة: React وTypeScript وVite.
- API: Node.js وExpress وTypeScript.
- الذكاء الاصطناعي: حزمة OpenAI الرسمية، ومفتاحها على الخادم فقط.
- البيانات: مجموعة قرآن ثابتة للقراءة فقط؛ لا توجد قاعدة بيانات لطلبات
  المستخدمين.

## التشغيل

تُشغّل واجهة `miyar` وخدمة `api-server` عبر تدفقي العمل المسجلين في Replit.
تحتاج خدمة API إلى السر `OPENAI_API_KEY` لمعالجة الادعاءات ومقارنتها بالدليل.
تعاد أخطاء الإدخال أو الخدمة باستجابة مضبوطة.

## الاختبارات

- `pnpm run typecheck` — اجتاز فحص TypeScript للمساحات.
- `pnpm --filter @workspace/api-server run typecheck` — اجتاز فحص TypeScript
  للخادم.
- `GET /api/healthz` — أعاد HTTP 200 و`{"status":"ok"}`.
- اختبار Quran للنقطة API أعاد HTTP 200 مع آية النحل 16:90 من Tanzil.
- اختبار إحالة البخاري 999999 للنقطة API أعاد نتيجة مكتملة بحالة «الدليل غير
  كافٍ» ولم يصفها بأنها موثقة.
- ظهرت الصفحات الثلاث في معاينة المتصفح. لم يُختبر ضغط زر التحقق وظهور بطاقة
  النتيجة في المتصفح ضمن هذا البناء.

## الخصوصية

لا يتطلب التطبيق حسابًا ولا ينشئ جلسات مستخدم أو سجلًا أو تاريخًا أو قاعدة
بيانات. يُرسل النص إلى OpenAI لتحليله وإنتاج النتيجة، ولا يحتفظ مِعيار بسجل
للطلبات. لا ينبغي إدخال بيانات شخصية أو سرية.
